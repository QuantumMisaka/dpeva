## 本轮结论核查实测

以下是在当前教学环境中进行的补充核查；四章 notebook 的实际计算与论文表格展示仍按上表区分。
结果保存于 [data/conclusion_audit.json](data/conclusion_audit.json)，可在教学环境中重跑：

```bash
python scripts/assess_conclusions.py
```

输出位于 `work/conclusions/assessment.json`，不启动训练、推理或 DFT。
本轮环境为 NumPy 2.5.4、SciPy 1.18.1、scikit-learn 1.9.1，数值线程设为 2；
脚本记录实际环境，其他环境的末位数值或名单可能变化。

**冷启动覆盖趋势保持。** 在同一个当前 PCA 空间中，用 3,000 个点比较 14 个保留主成分：

| 选择方法 | 平均分箱覆盖率 |
|---|---:|
| 当前 DIRECT | 98.34% |
| 历史 3,000 点名单 | 98.49% |
| 随机选择，20 个固定种子平均 | 89.66% |
| 上述 20 次随机选择的范围 | 88.12%–92.22% |

使用项目现有指标：每个 PC 划分 50 个区间，计算已占区间被选择样本覆盖的比例，再对 PC 求平均。
它衡量各主成分的边缘覆盖，不是完整高维联合覆盖或预测精度。
两份 DIRECT 名单的覆盖率相差约 0.15 个百分点，且都高于本轮 20 次随机结果，支持相同的覆盖优势结论。

**Joint 的新增信息趋势可见。** 将各方法选中的结构身份映射到共同的联合 PCA 空间，
比较新增点到历史训练集的最近距离中位数：当前 joint 为 0.08818，
同样新增 833 点的 normal 为 0.08129，历史 843 点为 0.08747。
距离是加权特征空间中的无量纲诊断，不是论文原指标或物理距离。
当前 joint 加上训练集的分箱覆盖率为 99.52%，历史为 99.51%，同数量 normal 为 99.76%；
因此这组证据支持“更偏向距离已有训练点较远的结构”，不支持“joint 在所有指标上都最好”。

按论文各自预算复算，四个 DPA3 分支的新增数为：DIRECT 1,000、joint 1,308、
UQ + DIRECT 1,000、UQ + joint 833。最后一种总训练量为 3,833/30,656 = 12.50%，
历史为 3,843/30,656 = 12.54%。按论文正文的表达精度，两者均为约 **12.5%**，
支持相同的数据预算描述；模型精度采用论文报告值，当前名单的精度需后续训练评估。

**二维 UQ 有互补信息，也保留盲区。** 相对单独用 QbC 下限定义低 UQ 区，
二维 tangent 分类把其中 1,020 点移到非 accurate 区（1,019 candidate、1 failed）。
但也有 1,373 个 QbC 不低于下限的点进入二维 accurate 区，所以它不是简单地收紧单轴边界。
以每帧最大原子力向量误差超过 1 eV/Å 作为事后诊断，单轴低 UQ 区有 129 点，
二维 accurate 区仍有 123 点；该阈值仅用于诊断，不是论文标准或采样输入。
不能把 `accurate` 类名解释为已经经过误差保证的正确预测。

要进一步复核论文精度结论，可以先从归档的预测/标签重新计算 Table 1/2 的误差，
再补充 Table S1 到 Table 3 的统计计算；这属于原实验结果的数值复核。
若要证明本次近等距换点后的名单仍达到相应精度，则必须用本次名单重新训练、推理和评估。

### 已定位的数值敏感性

本地两套环境对同一联合采样输入得到：

| 环境 | 新增点 | 与历史 843 点交集 |
|---|---:|---:|
| NumPy 2.5.4 / SciPy 1.18.1 / scikit-learn 1.9.1 / OpenBLAS | 833 | 737 |
| NumPy 2.4.1 / SciPy 1.17.0 / scikit-learn 1.8.0 / OpenBLAS | 842 | 742 |

两次标准化数组逐元素相同，PCA 坐标最大绝对差约 `6.77e-15`。
最终簇成员划分相同（ARI = 1，簇编号允许置换），但 3,000 个代表点中有 190 个发生替换。
其中 158 个发生替换的簇，最近和次近点到所用中心的距离差不超过 `1e-12`。
把第二套环境生成的 PCA 坐标交给第一套环境继续聚类、选点，簇标签和选中索引完全一致。
因此，**本次跨环境差异可由 PCA 末位数值变化触发**；这不是对全部历史差异成因的完整证明。

还检查了代表中心的实现：`BirchClustering` 使用
`dict(zip(model.subcluster_labels_, model.subcluster_centers_))`。
一个最终簇包含多个子簇时，同一键保留最后一个子簇中心，而非最终簇全部成员的均值中心。
上述两次运行有 38 个对应簇的代表中心距离相差超过 `1e-12`。
因此不能把所有差异都归于等距点排序：子簇构造与代表中心也需要核对。
此处保留原算法；直接换中心定义或加容差选点会改变方法，不能据此声称恢复历史结果。

### 如何自行诊断

在教程目录、已安装的教学环境中运行：

```bash
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  python scripts/diagnose_reproduction.py env_a
python scripts/diagnose_reproduction.py cold_f --stage cold --order F
```

脚本保存 JSON（版本、线程库、输入和阶段哈希、名单差异）和 NPZ（标准化数组、PCA 坐标、
簇标签、代表中心、子簇信息、选中索引）到 `work/reproduction/`。
默认 `joint`，也可用 `--solver full` 做求解器敏感性对照；修改求解器不等于恢复原配置。
输出前缀应不同，否则会覆盖同名诊断结果。

在另一环境中固定第一环境的 PCA 坐标，只检查下游步骤：

```bash
python scripts/diagnose_reproduction.py env_b_fixed \
  --pcs-from work/reproduction/env_a.npz
```

必须同时保留同名 JSON，脚本核对输入哈希、阶段和参考 PCA 数组哈希。
