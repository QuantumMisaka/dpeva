安装与环境准备（Installation）#

  • Status: active

  • Audience: Users / Developers

  • Last-Updated: 2026-10-21

1. 目的与范围#

本页说明 DP-EVA 的安装方式、Python 依赖、以及运行工作流所需的外部依赖。

2. 相关方#

  • 使用者：在本地或集群环境安装并运行工作流

  • 开发者：以可编辑模式安装并进行开发/测试

  • 平台维护：提供 DeepMD、ABACUS 与 Slurm 环境

3. Python 环境要求#

  • Python：>=3.10

  • 包名：dpeva

依赖定义以 pyproject.toml 为准。 以下 shell 命令面向 Linux / WSL。requires-python 声明包的 Python 下限；实际可用版本还取决于 所选 DeepMD、PyTorch 及计算平台，不能将它视为所有后端的完整测试矩阵。

3.1 按用途选择环境#

用途

环境与入口

20–30 分钟论文教学

克隆完整仓库，按 CPU notebook 教程运行 run.py；使用独立轻量环境，无需 DeepMD、GPU 或模型权重

实际 feature/train/infer/collect 工作流

按第 4 节安装完整环境，再运行 Quickstart

开发与文档维护

完整环境上启用 dev / docs，见第 5 节

SAI 或其他集群生产任务

使用验证过的后端环境及站点调度配置，见第 6 节

CPU 教程的启动脚本支持 Python 3.10–3.13，依赖在其 requirements.txt 中单独管理。 从仓库根目录运行 python3 examples/tutorials/paper_case/run.py 即可准备环境并执行四章； 首次安装需联网，之后可加 --offline。它不等价于安装完整 dpeva CLI 环境。

4. 从零准备 Local PyTorch 环境#

下面以支持 CPU 的 PyTorch 后端为例。先获取源码，再在仓库根目录创建独立 Python 环境；已有检出的用户直接进入仓库即可：

git clone https://github.com/QuantumMisaka/dpeva.git
cd dpeva
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install 'deepmd-kit[torch]>=3.2,<3.3' --extra-index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[deepmd]'
dpeva doctor
dp --version
python -c "import deepmd.pt.model; print('DeepMD PyTorch backend loaded')"

此处显式安装 DeepMD-kit 自己的 [torch] extra，由其 wheel 元数据选择匹配的 PyTorch 版本并带入 mpich 等后端依赖；CPU wheel 通过 PyTorch 的 CPU 索引取得。 这与只约束 DeepMD 版本的 DP-EVA [deepmd] extra 是两件事。 不要先安装不受约束的最新版 PyTorch 再只装裸 deepmd-kit：当前 3.2.0 wheel 的 torch extra 要求 PyTorch 2.11.0，并包含其自定义算子加载所需的依赖。

dpeva doctor 检查版本与命令能力，不能单独证明 DeepMD 自定义算子可加载； 上面的最后一条命令进一步检查 PyTorch 后端加载，包括二进制兼容性。 本次 Linux / Python 3.12、DeepMD 3.2.0、PyTorch 2.11.0+cpu 验证通过后端加载和 仓库 DPA3 夹具的单帧 CPU 推理；其他平台仍需在目标环境执行。 该 wheel 在此纯 CPU 环境会打印 libcudart.so.12 加载提示，但 CPU 推理正常完成； 这不代表 CUDA 可用，GPU 工作流仍需单独配置和验证。

GPU 安装与源码构建参阅 DeepMD-kit 的上游安装指南。 选择与驱动、DeepMD wheel 匹配的 PyTorch/CUDA 版本后，在实际计算节点检查 torch.cuda.is_available() 并加载后端。默认依赖和 deepmd extra 本身只约束 DeepMD-kit 版本，不负责选择 PyTorch 的 CPU/CUDA wheel；集群自编译环境使用 与其构建配置匹配的依赖，不直接套用本节的 PyPI wheel 配方。

示例输入随源码仓库提供。安装后按 Quickstart 使用 examples/recipes/quickstart/ 中的相对路径配置运行四阶段 Local 链路。

5. 其它安装方式与依赖边界#

5.1 Core：默认安装（含 DeepMD 兼容包络）#

默认安装在核心依赖中提供有界的 deepmd-kit>=3.1.2,<3.3，用于保留现有 3.1.2 运行包络。这个依赖边界是安装兼容性承诺，不是新的科学能力验证；能力 矩阵和 3.2 证据仍由显式 lane 单独管理。

核心依赖中的 dpdata>=1.1 是数据侧能力边界：读取 deepmd/lmdb 需要该下限， lmdb 与 msgpack 由 dpdata 自身引入。预置环境（--no-deps）若仍是 dpdata<1.1，deepmd/lmdb 输入会被明确拒绝；dpeva doctor 的 dpdata.lmdb 检查会报告实际可读性。

pandas 用于表格、UQ 和采样数据处理，packaging 用于运行时版本判定； 两者均为直接核心依赖。在项目根目录执行：

python -m pip install -e .

验证：

dpeva --help

想使用仓库自带夹具跑最小闭环，请先按第 4 节选择 PyTorch 后端，再阅读 Quickstart。

5.2 Dev：开发与测试依赖（可选）#

python -m pip install -e '.[dev]'

dev extra 只提供测试、格式化和类型检查工具，不额外改变核心 DeepMD 包络或 安装 atst-tools。需要明确 3.2 lane 的测试时，显式叠加下一节的 runtime extra。

5.3 DeepMD runtime：显式 3.2 运行时 lane#

默认安装已经提供 3.1.2 起的 DeepMD 兼容包络。训练、推理或特征工作流若要 显式解析 3.2 lane，在 core 安装上启用 DeepMD extra：

python -m pip install -e '.[deepmd]'

该 extra 的依赖范围是 deepmd-kit>=3.2,<3.3。这是用户环境的依赖解析 边界，不表示该范围内的每个版本行为完全等价。

验证运行时能力：

dpeva doctor
dp --version

doctor 是显式环境检查。稳定的 3.1.2--3.1.x 运行时会报告 deepmd 包络 可用，同时将 3.2 qualification 单独标为未声明；3.2 lane 则单独报告 qualification。旧版本、未来版本和 prerelease 不会绕过边界。

5.4 预置环境：由调用方承担全部依赖#

如果平台已经预置并验证了完整运行环境，可以显式跳过依赖解析：

python -m pip install --no-deps -e .

--no-deps 不是无依赖的默认安装。调用方必须自行提供 pyproject.toml 中的 全部依赖（包括 deepmd-kit），并保存环境版本与 dpeva doctor --json 结果。

5.5 Research production：研究生产精确锁定#

正式科研结果使用独立环境，并将 DeepMD 精确锁定为 deepmd-kit==3.2.0：

python -m pip install -e '.[deepmd]' 'deepmd-kit==3.2.0'

同时保存环境锁文件、dpeva doctor --json 和 dp --version 输出作为运行 记录。研究生产环境不能只依赖 >=3.2,<3.3 范围来声称可复现，也不能把范围内 其他版本未经验证的行为当作 3.2.0 等价物。

5.6 Exploration 可选依赖#

dpeva explore 通过可选 atst-tools backend 调用轨迹探索工作流。该依赖不进入核心安装，需要时单独启用：

python -m pip install -e '.[explore]'

验证：

dpeva explore --help
atst --help

说明：

  • dpeva[explore] 只安装 DP-EVA 的 exploration backend 依赖。

  • ABACUS、DeePMD 模型文件、赝势和轨道文件仍由具体 ATST 配置与运行环境提供。

5.7 文档构建依赖#

python -m pip install -e '.[docs]'
python scripts/run_gate.py docs_pr

docs 包含 Sphinx、主题、Markdown/图表扩展，以及文档检查用的 PyYAML 和 Python 3.10 下的 TOML 解析器；系统还需提供 make。它会同时安装核心依赖。 维护代码和文档时可合并安装 python -m pip install -e '.[dev,docs]'。

5.8 DPOSE 可选依赖#

dpose extra 提供 PyTorch，供需要自动微分或读取 PyTorch checkpoint 的 DPOSE 路径使用：

python -m pip install -e '.[dpose]'

已有 CPU/GPU PyTorch 环境时继续使用匹配的安装源。此 extra 不代替实际模型、 最后一层权重和后端适配要求；配置与适用范围见 配置指南。 论文 CPU notebook 使用归档委员会预测，不需要启用此 extra。

5.9 源码、发布包与示例数据#

本页的 -e 命令用于源码开发安装。部署固定源码副本时可在仓库根目录运行 python -m pip install .；需要完整 PyTorch 工作流时仍先按第 4 节准备后端。

截至 2026-10-21，PyPI 尚未提供可查询的 dpeva 发布记录，当前使用源码安装。 发布后可在已准备后端的环境中使用 python -m pip install 'dpeva[deepmd]'， 并按实际发布版本锁定依赖。源码版本与 PyPI 发布版本应分别记录。

wheel 只包含 src/ 下的 Python 包及声明的包数据；源码发行包通过 MANIFEST.in 排除 examples/tutorials/ 和集成测试模型权重。安装发布包不会取得论文教学数据、 notebook 或 Quickstart 所需的完整夹具；运行这些示例需另行克隆完整 Git 仓库。

6. 预置集群环境#

DP-EVA 的 DeepMD 工作流通过 dp 命令调用 DeepMD-kit（例如 dp train/test/eval-desc）。在 Slurm 环境中，建议通过 submission.env_setup 显式加载已锁定的 DeepMD 环境，不要依赖交互式 shell。 SAI 的 dpeva-dpa4 是项目已预置的测试环境； SAI 构建记录 以该环境和未入库的 test/deepmd-kit 源码检出为前提，记录的是已有环境的升级与验证，不是新账号 从零建环境的完整步骤。新账号先按本页第 4 节创建 Local 环境；集群 GPU 环境的 驱动、模块和队列配置应由集群维护者提供。
