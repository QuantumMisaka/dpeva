release-candidate report — is published as an annotated tag and a GitHub
Release, together with the community onboarding documentation patch requested
for the 2026-10-14 DeepModeling community seminar.

not from a code change. Patch and release are documentation-only; the plan was
authored 2026-10-11 and the tag/CI evidence below was produced on 2026-10-12
(CST).

## 3. What the release contains

The release notes carry the closeout scope: bounded `deepmd-kit>=3.1.2,<3.3`
default envelope with the explicit `>=3.2,<3.3` lane, strict config migration
that fails on conflicts and unknown fields, regular-only legacy model
discovery, current-attempt output freshness, fail-closed partial-failure
semantics, and the unchanged capability distribution of **3 supported / 8
experimental / 4 unsupported / 2 blocked-upstream**. No new scientific
qualification, dependency range, or capability is claimed.

Patch content (commit `44a6e19..0723090`):

- `README.md`: model/data acquisition pointers (AIS Square model id 343,
  dataset id 306; `DPEVA_DPA3_MODEL_PATH` / `DPEVA_DPA4_MODEL_PATH` overrides)
  and the documentation site entry.
- `docs/guides/smoke-demo.md`: the `feature -> train -> infer -> collect`
  smoke loop on the tracked fixtures, with verified artifacts, completion
  markers, timings, alignment traps and explicit smoke-only limits.
- `docs/guides/sai-quickstart.md`: SAI environment, install/`dpeva doctor`
  self-check, submission essentials, and links to the single-sourced Slurm
  traps in [slurm.md](../guides/slurm.md) and
  [the DeepMD-kit SAI build guide](../guides/developer/deepmd-kit-sai-build.md).
- Navigation: `docs/README.md`, `docs/guides/README.md` and
  `docs/source/index.rst` (toctree) wire the new pages in; the Sphinx toctree
  entry is required because an unlisted page fails the `-W` docs build.
- `tests/integration/data/README.md`: corrected the claim that all large
  DeePMD models are untracked (`DPA-3.1-3M.pt` has been tracked since
  `da7babf`; only the DPA4 family is external).
- Freshness repair: ten living documents were re-reviewed and their
  `last-updated` refreshed, restoring `docs_freshness`.

## 6. Smoke evidence

The smoke demo was executed locally before publication on the tracked fixtures
(`feature -> train -> infer -> collect`, Local backend, `numb_steps=30`,
`num_models=3`): 44 s / 1 min 52 s / 1 min 33 s / 8 s, each step exit 0 with
`DPEVA_TAG: WORKFLOW_FINISHED` in the documented log location. The tiny
fixtures select zero frames at `direct_n_clusters=3`, which is recorded as an
expected limitation rather than a sampling result.

## 7. Known limitations and follow-ups

- The fixture smoke run was executed on a single 8 GB consumer GPU with the
  locally built DeepMD-kit `3.2.0b1.dev67`; `dpeva doctor` classifies that
  development version string as outside the qualified 3.2 lane even though its
  `test`/`eval-desc`/`embed` CLI surface is present. This is an environment
  observation, not a release claim.
- This cut does not re-run the closeout's package/wheel acceptance; that
  evidence remains bound to the revision recorded in the closeout report.
- The developer-guide revision history already carried a `v0.8.2` entry
  (2026-09-06), so this cut did not add a second one.
- `docs_freshness` is a rolling 90-day window: the refreshed living documents
  will need another review cycle around 2027-01.
