# DeepMD-kit 3.2 Compatibility Qualification

## Decision

This report records the evidence available for the DeepMD-kit 3.2
compatibility lane. It is a bounded engineering qualification record, not a
scientific performance result. No capability is promoted to `supported`:
the manifest currently has zero supported records, and the only SAI attempt
ended before its payload ran.

The compatibility manifest and this report must be updated together. A
DeepMD version number alone is never sufficient for promotion.

## Manifest status distribution

The current 15-record manifest (`src/dpeva/compatibility/deepmd-3.2.json`)
has the following explicit distribution:

| Status | Records |
|---|---:|
| `supported` | 0 |
| `experimental` | 9 |
| `unsupported` | 4 |
| `blocked-upstream` | 2 |

The two CPU non-PBC DPA4C records (`eval-desc` and `inference`) remain
`blocked-upstream` pending [DeepMD-kit issue #6002](https://github.com/deepmodeling/deepmd-kit/issues/6002)
and a fixed-version non-PBC contract. Neither record is promoted by this
report.

## CPU contract evidence

The local `ft2dp-post` environment reported exactly `DeePMD-kit v3.2.0`.
Running the DeepMD contract lane locally produced **6 passed / 4 explicit
fixture skips**. The skips are the named missing protected model/data
fixtures; no full regular/EMA or DPA4C positive-model qualification was
executed in this local run. Thus these results demonstrate the contract
harness and the enabled cases only; they do not establish universal CPU or
GPU correctness.

The CI contract lane is intentionally stricter: it downloads a protected
fixture bundle, verifies the configured URL and SHA-256, sets
`DPEVA_DEEPMD_CONTRACT_REQUIRED=1`, and rejects missing fixtures or skipped
cases. The required command is:

```text
pytest -m deepmd_contract tests/contract/deepmd -q
```

The local fixture skips cannot be substituted for that CI-required positive
fixture evidence.

## Promotion rule and conclusion

Promotion requires the exact manifest key's verification command to pass and
the referenced evidence to exist. Repository-local references must resolve to
files. A capability whose environment is `sai-*` additionally requires both
CPU-contract and SAI-qualification references. Unsupported and
blocked-upstream records cannot be promoted by an environment/version check.

The present evidence satisfies none of the conditions for a `supported`
record. Keep all nine experimental records unchanged, keep the four policy
`unsupported` records unchanged, and keep both non-PBC records blocked by
issue #6002.

## Retry and ownership boundary

No second SAI job is submitted under this qualification. A retry requires
new explicit authorization and an operations diagnosis of the scheduler
cancellation (including a clean submission environment and a bounded resource
decision). Once authorized, the retry must produce complete immutable
`qualification.json` evidence and pass `--require-complete` before any
manifest edit is considered.
